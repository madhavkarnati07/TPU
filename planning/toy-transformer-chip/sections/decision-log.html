The architecture decisions locked by the implemented and verified chip.

Initial Decisions

Decision Status Notes
Planning format Chosen Use HTML index and subsection pages with interactive control-flow diagrams.
Implementation status Complete Python, RTL, wrapper tests, powered gate simulation, hardening, and precheck pass locally.
Primary purpose Chosen Educational and fun; favor simple, explainable design over optimization-driven complexity.
Number format direction Locked Use signed int4 for all loaded operands and projection/final outputs.
Q/K/V projection location Locked Assume the chip computes Q, K, and V projections from input embeddings and integer projection matrices.
Toy shape Locked Use sequence length 4, embedding width 2, Q/K/V width 2, and one attention head for Phase 2 sizing.
Accumulator width Locked Use signed 16-bit accumulators for the first hardware-shaped model; clamp or requantize stage outputs back to int4 where needed.
High-level architecture target Locked Use two reusable MAC lanes. Both dimensions run together for projection and weighted V; scores serialize through lane 0.
Attention direction Implemented Run one complete serialized single-head attention pass over four 2D tokens.
Softmax direction Locked Use clipped-linear attention for the first hardware-shaped model: B = 4, u_i = max(0, B + score_i - max_score), then normalize weighted V with a Q0.8 reciprocal LUT and round-to-nearest.
Int4 clamp behavior Locked Use saturating clamp to signed int4 range [-8, 7] after projection requantization and final normalization. Do not wrap.
Debug readback Implemented Keep READ_DEBUG as an observability command so the host can drain intermediate values and compare them with the Python model.
Design sequencing Chosen Validate the MAC primitive, then verify the complete attention transaction at source RTL and powered gate level.

Closed Numeric And Protocol Decisions

  1. Signed Q0.8 products round to nearest with ties away from zero.
  2. READ_DEBUG selectors 0x00 through 0x08 cover status and retained intermediate values.
  3. The FSM serializes load, projection, score, max, clip, weighted V, normalization, debug, and TX phases.
  4. The demonstration combines exact numeric traces, simulation checks, and browser animation.
