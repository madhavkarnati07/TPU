Architecture Options

Candidate chip scopes, from safest to most transformer-like.

Option A: Single MAC Engine

A tiny multiply-accumulate datapath receives signed bytes, accumulates a dot product, and returns the result. The host sequences every higher-level operation.

  • Lowest risk and easiest to explain.
  • Directly maps to dot products in matmul and attention.
  • Less visually exciting than a systolic array.

Option B: 2x2 Matrix-Multiply Tile

A small systolic or scheduled MAC array computes one 2x2 matrix product tile. Larger products are decomposed and streamed by the host.

  • Closest to the existing TinyTapeout TPU reference.
  • Good educational bridge from matrix multiplication to attention.
  • Still small enough to keep understandable.

Option C: Serialized Toy Attention Core

A tiny controller runs a fixed demonstration of Q/K/V dot products and value accumulation, using host-streamed operands and minimal on-chip state. The selected number format is int4 if it helps fit a larger educational example.

  • Most aligned with the transformer story.
  • Requires the most careful protocol and state-machine design.
  • Softmax should be simplified, approximated, or handled partly by the host.
  • Only remains a candidate if Tiny Tapeout feasibility checks look reasonable.

Selected Architecture

This page is now a background appendix. The active Phase 2 target is the High-Level Chip Architecture: two reusable MAC lanes in a fixed int4 single-head toy attention core. Both lanes compute projection and weighted-V dimensions together; score dot products serialize through lane 0. The hardened implementation confirms that this option fits a Tiny Tapeout 2x2 tile.
